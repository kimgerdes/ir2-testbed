# Demo queries (testbed SciFact / NFCorpus: BM25 | MiniLM, the spring bi-encoder | static-retrieval-mrl-en-v1)

- **Hero**: "Individuals with low serum vitamin D concentrations have increased risk of multiple sclerosis." (SciFact). The labelled abstract, *Past exposure to sun, skin phenotype, and risk of multiple sclerosis*, never names vitamin D in its title. It is rank 1 for the static model, 11 for BM25 and 16 for MiniLM: BM25 has no key word to match, since the text never says vitamin D. We have not isolated why static ranks it first: the cosine between the phrases "vitamin D" and "sun exposure" is low in both models (0.08 static, 0.26 MiniLM), so it is not a simple phrase-to-phrase link.
- **Failure**: "The locus rs647161 is associated with colorectal carcinoma." (SciFact). Rank 1 for BM25 and MiniLM, 8 for static. The tokenizer cuts `rs647161` into `rs ##64 ##7 ##16 ##1`: five generic digit pieces whose fixed vectors carry no identity once they are averaged with the rest of the claim. BM25 matches the exact identifier, and MiniLM's attention composes the pieces. Static models lose exactly where one rare exact token decides relevance.
- **Wildcard**: proposed on the spot by the discussants or the room. Backups: "Zoloft" (NFCorpus: static rank 1, MiniLM 20, BM25 > 100: no document contains the word; static ranks first a study that names sertraline, its generic name), then the negation pair "Macrolides protect against myocardial infarction." / "Macrolides have no protective effect against myocardial infarction.": the static model returns the same abstract first for both, and SciFact counts it relevant for both.

Demo queries were chosen from the test queries after the runs, for presentation only: nothing was tuned on them.
